## Решения

<!-- Куда отнесли матчи с другими статусами и почему. Какие ещё неочевидные случаи нашли в данных и как обработали. -->

- **Фильтр.** Добавил отдельную вкладку «Текущие» для `live`. «Предстоящие» — `scheduled` и `postponed`: перенесённый матч всё равно предстоит сыграть. «Завершённые» — только `finished`.
- **Фильтр строится по статусу, а не по времени.** У `m5`/`m6` статус `scheduled`, хотя дата уже прошла: источник правды — сервер, а часы устройства могут врать.
- **`startsAt: null`** у перенесённого матча: показываем «Дата не назначена», при сортировке такие матчи уходят в конец.
- **`score: null` и счёт `0:0`.** Отсутствие счёта (`null`) показываем прочерком, а `0:0` — как реальный счёт. Поэтому проверка на `null`, а не на «ложность».
- **`live` с `minute`:** показываем «Идёт · 67'».
- **Время** парсится из ISO-строки в `Date` и форматируется через `Intl.DateTimeFormat` без явного `timeZone`, то есть в часовом поясе устройства.
- **Ответ сервера валидируется** (`src/api/matches.ts`): битая запись пропускается и не роняет весь список, а неожиданный формат ответа даёт понятную ошибку.
- **Утечка таймера в `UpdatedAgo`.** `setInterval` никогда не останавливался: таймер продолжал тикать после ухода компонента с экрана, а в режиме разработки (где React запускает эффекты дважды) их становилось два. Добавил `clearInterval` в функцию очистки эффекта.
- **Сохранение избранного.** Пока хранилище не прочитано, ничего не записываем, иначе пустой стартовый список затёр бы сохранённый. Прочитанное объединяется с тем, что пользователь успел отметить за это время. Избранное хранится по `id` матча: если сервер переиспользует `id` в следующем туре, отметка «переедет» на другой матч.
- **Ошибка при обновлении** не стирает уже загруженный список: сверху показывается баннер с кнопкой «Повторить». Повторный запрос отменяет предыдущий через `AbortController`, чтобы старый ответ не перезаписал новый.

## Баги из части 2

<!-- Для каждой жалобы: почему так происходило (своими словами) → что исправили. -->

1. Звёздочки: isFavorite проверял Boolean(favorites.indexOf(id)) - для отсутствующего матча indexOf даст -1, = true, поэтому горели все звезды. Матч на позиции 0 => false => звезда гаснет. toggle менял сам массив состояния (push/splice) и передавал в setFavorites ту же ссылку. React сравнивает по ссылке, не видит изменений и не перерисовывает экран, изменение всплывало только при иной перерисовке. Проверка через includes, в toggle каждый раз новый массив через setFavorites. Хук вызывается один раз в экране, а не в каждой карточке.
2. «Обновлено N сек назад»: Эффект с '[]' запускался один раз, таймер получает seconds = 0, каждую секунду выполняется setSeconds(0 + 1) и счётчик = 1. since не использовался, счетчик от появления компонента на экране, а не от момента загрузки, поэтому новый since после обновления его не сбрасывал. Секунды вычисляются как now − since, а таймер только раз в секунду обновляет now.
